# Legacy desktop archive workflow

The [terminal UI](terminal-ui.md) is the current interactive workflow, and both default Send to archive shortcuts open it. This guide describes the older Tkinter window, still available through `archivebench-desktop --root "D:\Project\SD 1" "D:\Project\SD 2" "D:\Project\clip.mov"` or the installer's legacy mode. References below to the terminal-only shortcut mean that legacy mode. The proxy watcher remains separate and unchanged.

The archive window accepts multiple folders, individual clips, or a mixture on one source drive. Add folder and Add files extend the list; overlapping selections are deduplicated and existing checkmarks are retained. Paths beneath the common source folder are preserved, so `SD 1/clip.mov` and `SD 2/clip.mov` cannot collide. The proposed output is Archived Footage beneath that common folder. Review or change that destination when combining unrelated projects. Different source drives require separate jobs; the output may be on another drive. The terminal-only shortcut retains its single-folder workflow. Cleanup still requires one project/archive folder.

The desktop selector lists eligible clips, excluding proxies and generated archives. Double-click a row or press Space to toggle its selection; select all/none buttons are available. If an `Original Footage` subtree exists, it is selected by default and other clips start unchecked. The proposed destination is `Archived Footage` beside that subtree when selected directly, or within the selected project. Choose another destination to keep multiple preset versions.

Select a measured JSON preset and review its chroma statement. Container, audio copy/AAC/none, one-based dropped audio tracks, data/cover-art reject/drop, and timecode preserve/reject/drop are explicit job choices. Preserving timecode requires MOV/MP4. Unknown or incompatible mux combinations stop that clip in preflight; a listed container is not proof your editor supports it. Sidecars still require separate handling. AAC uses 192 kbps per channel. All video presets remain lossy.

The first button saves a job and shows preflight in the terminal. Type `ARCHIVE` to execute. Output names retain original filenames plus `.archive.mov`, `.archive.mp4` or `.archive.mkv`. Progress shows file count, percentage, speed and approximate remaining encode time; verification is a separate phase. Individual encode/verification failures are recorded and later eligible clips continue. Low disk space and source/output identity conflicts stop the batch. Originals remain intact.

Repeat the same selection, settings and destination to resume. Completed outputs must match hashes. Interrupted clips restart; saved jobs cannot be silently overwritten by new presets, policies or selections. Last preset and same-project destination are remembered. Old Proxy Watcher manifests are not imported or converted.

Use `archivebench acceptance inspect --output DESTINATION`, then record actual visual and editor review through the documented [acceptance workflow](editor-acceptance.md). `archivebench-desktop --root DESTINATION --cleanup` shows only currently accepted, verified originals. Nothing starts selected. Deletion is separately confirmed and rechecks the whole acceptance binding and hashes. It does not move originals that were not worth encoding.

The previous Proxy Watcher archival engine remains available only for its existing manifests and rollback until actual editor acceptance completes. Its proxy maker remains supported and unchanged. Native GUI construction, synthetic MOV/MP4 preservation and resume tests do not replace a real editing-project reopening check.
