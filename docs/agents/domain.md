# Domain documentation

This repository has one domain context. Before exploring or changing domain behavior, read root `GLOSSARY.md` and relevant records in `docs/adr/` when present. Proceed when they are absent.

Use the glossary's terms in specs, tickets and code discussions. Add definitions as terms are settled; keep implementation details in the spec.

Record an architectural decision only when it is costly to reverse, surprising without context and based on a real tradeoff. Surface conflicts with an existing decision before changing its behavior.
